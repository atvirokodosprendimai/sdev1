# ADR-034: The read verb is READ, and SELECT is reserved so that typing it says so

**Status:** Accepted
**Date:** 2026-09-05
**Owner:** M
**Spec:** None — no spec stage
**Cross-references:** `docs/adr/README.md`, `docs/adr/ADR-011-query-language.md`, `docs/adr/ADR-022-write-statements.md`, `docs/adr/ADR-027-evaluator.md`, `docs/adr/ADR-032-map-generation.md`, `docs/QUERY-LANGUAGE.md`
**Governs:** `internal/core/ql/**`
**Enforced-by:** `internal/core/ql/read_test.go::TestSelectIsRefusedByName`
**Invalidates:** none — it renames a verb ADR-011 introduced and changes nothing ADR-011 decided about what the verb MEANS
**Served-path change:** `READ * FROM planet-3` is the read statement. `SELECT` no longer parses, and typing it produces an error that names its replacement.

## Context

The language's read verb was `SELECT`, borrowed from SQL. The rest of the
language deliberately is not SQL: there is no `INSERT`, no `UPDATE`, no `DELETE`,
because the store appends and those verbs would describe a data model this system
does not have. ADR-022 says exactly that.

★ `SELECT` was the one verb left implying the family. A caller who reads
`SELECT` reasonably expects its siblings, and the first thing they learn is that
four of them will never exist. The verb was doing the opposite of its job.

`READ` says what happens and implies nothing that is not true.

★ **The agent surface had already picked the same word.** ADR-013's tool registry
names its reading verb `read` (`mcpsurface.VerbRead`), and it compiled to a
`ql.Select` — so the one place in this system that had to choose a name for
callers, without a SQL habit to inherit, chose this one. That is not proof, but it
is the closest thing to evidence available for a naming decision, and it was found
while making the change rather than argued in advance.

⚠ This is a rename with a large blast radius — the keyword, the AST type, the
evaluator's entry point, the session, every published example and every page that
teaches the language. It is worth doing now, while the language has no users and
no stored query text, and it will not be worth doing later.

## Existing Primitives Audit

- `internal/core/ql` (ADR-011): supplies the lexer's keyword table, the AST and
  the parser. **Renamed, not restructured** — the grammar, the clauses and the
  time semantics are untouched.
- `internal/core/eval` (ADR-027): supplies the evaluator's entry point.
  **Renamed for the same reason as the type** — see rule 2.
- `internal/core/session` (ADR-022): dispatches statements. **Renamed.**
- The published documentation: **regenerated by hand and gated** — two existing
  tests parse every example on those pages and enumerate the package's exported
  identifiers, so a partial rename fails rather than drifting.
- A compatibility alias accepting both spellings: **rejected below.**

## Decision

**The read verb is `READ`. `SELECT` stays RESERVED and is refused by name.**

1. **`READ` replaces `SELECT` as the verb.** Everything else about the statement
   is unchanged: the projection, `FROM`, `WHERE`, and both time clauses mean
   exactly what ADR-011 and ADR-027 say.

2. **The AST type and the evaluator entry point are renamed too** — `ql.Read`,
   `eval.Read`. ⚠ Not cosmetic, and ADR-032 is the precedent: a type called
   `Select` behind a keyword called `READ` is a name that says one thing and means
   another, which is the exact shape of the trap that record removed. A rename
   that stops at the surface leaves the confusion where the code is.

3. **`SELECT` remains a RESERVED word and is refused with a message naming
   `READ`.** ★ It is not simply removed. Every example in the world says `SELECT`,
   so a caller who types it should be told what to type instead — not handed
   "expected an attribute name" from a parser that has started reading their verb
   as a column. A named refusal is what this language does everywhere else.

4. **`SELECT` is NOT an accepted alias.** ⚠ Two spellings of one verb is two
   things to document, two things to test, and a permanent question about which
   is canonical. The refusal is a migration aid; an alias is a second language.

5. **Backticks still make `SELECT` an identifier.** ADR-021 made every keyword
   addressable as an attribute name, and reserving a word must not take that
   away — an attribute genuinely called `select` stays writable as `` `select` ``.

6. ⚠ **Five TEST FUNCTIONS keep `Select` in their names, deliberately.**
   `TestSelectRoundTripsThroughTheAST`, `TestAssertThenSelectReadsItBack`,
   `TestASelectRunsAgainstARealLeaf`, `TestASelectReadsOneEntityOnce` and
   `TestASelectWithAStoreReadsThroughTheStore` are named by the acceptance fences
   of ADR-011, ADR-022 and ADR-027. Renaming them rewrites those fences, which
   changes their digests, which invalidates every mutant already recorded against
   them. ★ That is a trade of real evidence about the evaluator and the session for
   a name no caller types, and it is the wrong way round. Unlike the AST type in
   rule 2, a test name is not a surface anybody calls and cannot mislead a caller
   into writing the wrong thing — it can only look dated. Recorded here so the
   inconsistency reads as a decision rather than a missed occurrence.

**What would falsify this.** `SELECT * FROM planet-3` producing a parse error that
does not name `READ`, or producing rows. That is the falsifier in `Enforced-by:`,
and it is what removing the keyword outright would give.

## Alternatives Considered

- **Keep `SELECT`.** No work, and it is what everybody knows. Rejected: it is the
  one verb implying a family of siblings this store will never have, so it teaches
  the wrong model at the very first word a caller types.
- **Accept both spellings.** It removes the migration problem entirely. Rejected
  under rule 4: two ways to say one thing means both must be documented, both must
  be tested, and every reader has to wonder which is canonical — for a language
  whose whole argument is that it says only what it means.
- **Remove `SELECT` from the keyword table entirely.** Simplest, and a
  three-line change. Rejected under rule 3: it then lexes as an ordinary
  identifier, so `SELECT * FROM x` fails somewhere inside the projection with a
  message about attribute names, and the caller has to work out that their verb
  was the problem.
- **Rename the keyword and leave the Go type as `Select`.** Much smaller diff.
  Rejected under rule 2: it is precisely the `Version`/`Generation` trap ADR-032
  removed one record ago — a name that means something other than what it says,
  sitting where the next person will reach for it.
- **`GET`, or `FETCH`.** Both are shorter. Rejected on meaning: `GET` implies a
  single addressed thing, which is what this statement does today and is not what
  it will do once a set can be read; `FETCH` implies going somewhere, which is a
  storage concern rather than a question.

## Component / Boundary Impact

No component boundaries move. `internal/core/ql` keeps owning what a statement may
say, `internal/core/eval` what it means when it runs, and `internal/core/session`
how one is dispatched.

| Surface | Change | Producer | Consumer(s) |

| `READ` keyword | new — the read verb | T1 | callers |

| `ql.Read` | RENAMED from `ql.Select` | T1 | eval, session |
| `eval.Read` | RENAMED from `eval.Select` | T1 | session |

## Inter-task Contracts

| Contract | Producing task | Consuming task(s) | Breaking? |
|----------|----------------|-------------------|-----------|
| `ql.Read`, `eval.Read` | T1 | — | Yes, and deliberately: the old names are gone rather than deprecated |

## Consequences

- **Positive:** The first word of the language stops implying three verbs that
  will never exist.
- **Positive:** Typing the old verb tells you the new one, so the rename costs a
  reader one error message rather than a search.
- **Negative:** Every published example, every page and every test changes. That
  is the cost of doing it at all, and it is paid once — the two documentation
  gates make a partial rename fail rather than drift.
- **Negative:** `SELECT` occupies a keyword slot while meaning nothing. It is a
  word nobody should want as a bare attribute name anyway, and backticks still
  reach it.
- **Neutral:** No semantics change. A statement means exactly what it meant.

## Out of Scope

- Reading a SET of entities rather than one named entity (deferred: `docs/adr/BACKLOG.md` §20 — a separate decision about what `FROM` may name)
- Paging a result (deferred: `docs/adr/BACKLOG.md` §20)
- Renaming the five TEST FUNCTIONS whose names contain `Select` (permanent: boundary: rule 6 — they are named by accepted acceptance fences, and renaming them would discard mutation evidence in exchange for a name no caller types)
- What the statement MEANS (permanent: boundary: ADR-011 owns the grammar's meaning and ADR-027 owns evaluation; this record changes a word)
- Renaming any other verb (permanent: boundary: `ASSERT`, `RETRACT`, `SEARCH` and `TRAVERSE` already say what they do, and churn without a reason is worse than an imperfect name)

## Risks

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| The rename is partial — code renamed, docs not | High — 300-odd occurrences across code, tests and two teaching pages | Med — the documentation teaches a language that no longer parses | Two existing gates: one parses every published example, one enumerates the package's exported identifiers against the pages |
| The Go type keeps the old name | Med — it is a much smaller diff | Med — a name that says one thing and means another, one record after ADR-032 removed exactly that | Rule 2 |
| `SELECT` is removed rather than reserved | Med — it is the obvious way to delete a keyword | Med — the error lands inside the projection and never mentions the verb | Rule 3, and the falsifier asserts the message names `READ` |
| An alias is added later "for compatibility" | Med | Med — two spellings, permanently | Rule 4, recorded so it arrives as a proposal against a decision |

## Rollback

Reverting is another rename. ⚠ Nothing on disk holds query text, so there is no
migration either way — which is exactly why this is worth doing now and will not
be later.

## Follow-ups

- [ ] When `FROM` can name a set rather than one entity (`BACKLOG.md` §20), confirm `READ` still reads correctly at the call site — a verb chosen for a single-entity read should be checked against the plural case before that lands.
- [ ] Revisit rule 3 once nobody types `SELECT` any more; a reserved word that has done its teaching job is a keyword slot that could be released, and that is a decision rather than a cleanup.
